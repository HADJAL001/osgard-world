## 1. Резюме аудита

Это не пустой проект и его не следует заменять новым шаблоном. Репозиторий уже содержит React 19 + TypeScript + Vite, публичные статические игровые сборки, отдельные игровые страницы, каталоги, согласие на аналитику, коммерческий API, форму заявок, рекламные/спонсорские форматы, административную страницу и многоуровневые smoke-тесты.

### Подтверждено в исходниках

- **Игры:** каталог OSGARD PLAY сообщает о 12 игровых мирах; маршруты и статические сборки включают TIME/«Империя времени», SWARM, NULL//SHIFT, INHERIT, REMIX, CIVIC CASCADE, PATINA ATELIER, SIGNAL RUN, CASCADE LAB, AFTERIMAGE//RUN, AETHER GRID и HEIST//ECHO.
- **Страницы игр:** `src/GameDetailPage.tsx` содержит жанр, описание, управление, поддерживаемые устройства, функции игры, fullscreen/поделиться/избранное и рекомендации.
- **Экосистема проектов:** `/games/ecosystem/` содержит ровно десять проектов владельца, поиск, фильтры, UTM-разметку исходящих переходов, ссылки на разработку и контакты.
- **Монетизация и партнёры:** `/games/partners/` и commerce-admin описывают рекламные/спонсорские форматы. Инвентарь по умолчанию не активирован и требует ручного подтверждения; нельзя показывать эти форматы как проданные или как подключённую рекламную сеть.
- **Аналитика и согласие:** `public/games/consented-analytics.js` и `src/core/eventQueue.ts` используют явное согласие, ограниченную очередь и allow-list событий. Отзыв согласия предусмотрен.
- **Коммерческий API:** продуктовые определения и серверные проверки находятся в `services/osgard-commerce-api/`. В `public/games/commerce-config.json` `apiBaseUrl` пустой; клиент может пробовать same-origin API только если health-check подтверждает ожидаемый сервис и готовую базу. Иначе безопасный сценарий — сообщить, что онлайн-отправка недоступна, и дать пользователю ручной канал связи.
- **Защита платёжных функций:** настройки/прайс-ID Stripe предусмотрены в коде, но сами по себе не доказывают, что Stripe подключён или live-платежи включены. Выпуск платежей, подписки, права доступа, отмены и возвраты требуют отдельного production-проверочного цикла.

### Не подтверждено в рамках этого аудита

- Мы не могли получить HTML production-доменов из браузерного fetch в этой среде: запросы вернули cache-miss/недоступный URL, а прямое сетевое соединение к GitHub из контейнера не работало. Поэтому не утверждаем, что опубликованный сайт проверен сейчас или что production изменён.
- Текущее состояние десяти внешних доменов **не следует угадывать** по поисковой выдаче. Новый workflow после добавления в default branch ежедневно создаёт реальный HTTP-отчёт.
- Никакая автоматическая проверка главной страницы не доказывает безопасность продукта, владение доменом, законность условий, качество пользовательского сценария или пригодность для платной рекламы.
- Мы не видели реальные production-секреты/состояние БД/настройки платёжного провайдера; их значения не требуются для проверки публичных главных страниц.

## 2. Изменение в этой ветке

Добавлен workflow `.github/workflows/external-project-healthcheck.yml`:
- ежедневная проверка десяти HTTPS-домашних страниц;
- ручной запуск из GitHub Actions;
- ограниченное время выполнения;
- только `contents: read`, никаких секретов или платёжных ключей;
- JSON-артефакт на 30 дней даже при ошибке строгого режима;
- строгий режим — только по явному ручному выбору; обычный запуск сообщает о недоступности, но не делает кратковременный сетевой сбой основанием для неинформативного падения всех рутинных задач.

Отчёт содержит HTTP-код, длительность ответа, конечный URL/host, заголовок страницы, классификацию ошибки и отдельный promotion gate. Ветка использует существующий `scripts/external-project-healthcheck.mjs`, а не второй, расходящийся список доменов.

## 3. Модель бренда и UX

В существующем Games-хабе уже задан выразительный тёмный бренд: обсидиановая основа, кислотно-лаймовый маркер, металлический нейтральный, циановый и фиолетовый дополнительные цвета; геометрическая эмблема применяется в каталоге и favicon. Сохранять её нужно, а не заменять чужим или случайным знаком.

Три рабочие варианта арт-направления:
1. **Obsidian / Acid Lime** — действующее направление для OSGARD PLAY; хорошо различимо на тёмном фоне и уже связано с каталогом.
2. **Obsidian / Ice Cyan** — можно использовать как тематический акцент для тактических/инженерных игр.
3. **Midnight / Champagne** — более спокойный стиль для страниц услуг и спонсорских предложений.

Рекомендация: оставить вариант 1 общесистемным брендом; циан/фиолетовый разрешать на игровых обложках и внутри игровых миров, не менять общую навигацию. Не использовать рейтинги, отзывы, онлайн-счётчики и доходы без источника реальных данных.

## 5. Три иллюстративных финансовых сценария

Это **арифметическая чувствительность, а не прогноз**, потому что в аудите нет достоверных данных о текущих визитах, запусках, fill rate, eCPM, расходах и конверсии.

Формулы:
- Начала игры = визиты × доля начавших игру.
- Сессии = начала игры × среднее число сессий.
- Потенциальные показы = сессии × рекламных возможностей за сессию.
- Сервированные показы = потенциальные показы × fill rate.
- Рекламный доход = сервированные показы / 1000 × фактический net eCPM.
- Ожидаемые контракты = визиты × конверсия в заявки × доля квалифицированных заявок × доля выигранных предложений.

| Допущение за месяц | Консервативный | Базовый | Оптимистичный |
|---|---:|---:|---:|
| Визиты | 5 000 | 25 000 | 100 000 |
| Доля запуска игры | 15% | 25% | 35% |
| Сессий на стартовавшего | 2 | 3 | 4 |
| Рекламных возможностей за сессию (вне активного момента) | 2 | 2 | 2 |
| Fill rate (предположение) | 35% | 55% | 70% |
| net eCPM (предположение) | €1.50 | €3.00 | €5.00 |
| Расчётный рекламный доход/месяц | €1.58 | €61.88 | €980.00 |

Реклама в расчёте не гарантирует дохода: фактический результат зависит от согласия, географии, политики сети, блокировщиков, формата и реального заполнения. До подключения провайдера реальная рекламная выручка равна **€0**.

Для чувствительности к заявкам (также только модель): при конверсии визит→заявка 0,2% / 0,4% / 0,6%, квалификации 30% / 30% / 35%, закрытии 10% / 15% / 20% и условном денежном вкладе одного проекта €750 / €1 500 / €2 000 получим 0,3 / 4,5 / 42 ожидаемых проекта и €225 / €6 750 / €84 000 ожидаемого вклада. Это не cash-flow и не гарантированная прибыль: сделки могут не закрыться, вклад/расходы не подтверждены, а цикл продаж может выходить за рамки месяца.

Чувствительность сильная: удвоение визитов удвоит показы при неизменных остальных коэффициентах; снижение fill rate с 55% до 30% уменьшит средний расчёт рекламы примерно на 45%; отсутствие настроенного API/провайдера означает, что денежное событие не должно маркироваться как оплаченная операция. Перед финансовыми решениями заменить все допущения фактическими событиями аналитики и отчётами провайдера.

## 6. Выпуск и операционные ворота

Перед merge/deploy:
- [ ] Запустить `npm run qa:external-project-healthcheck` и проверить новый контракт workflow.
- [ ] Из GitHub Actions выполнить workflow вручную в warning-only режиме; получить первый реальный JSON health report.
- [ ] Разобрать недоступные URL вручную и проверить цепочку редиректов/HTTPS.
- [ ] Запустить `npm run qa:games-portal`, `npm run qa:games-detail`, `npm run qa:ecosystem-directory`, `npm run qa:ecosystem`, `npm run qa:project-intake`, `npm run qa:privacy-consent` и `npm run qa:release`.
- [ ] Создать preview/production build и запустить `npm run qa:production-routes` после deployment.
- [ ] Подтвердить, что commerce API здоров, база готова, env secrets настроены на хостинге, админ-панель защищена, тестовые платежи и отмены прошли.
- [ ] Рекламную сеть подключать только после аккаунтной модерации, consent-проверки и проверки placements. Никакой реальной рекламы эта ветка не включает.
