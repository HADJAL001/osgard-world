# OSGARD WORLD GAMING — технический аудит и статус внедрения

Дата аудита: 13 октября 2026 года. Источник кода: репозиторий `HADJAL001/osgard-world`; контрольная точка основной ветки на момент аудита — `2f2b55bf3c125727102e849143e95dcfc488a12b`. Изменения игровой платформы готовятся в отдельной ветке `feat/osgard-premium-games-platform`; до слияния и успешного production deploy они не считаются опубликованными.

## 1. Обнаруженная архитектура

- Frontend: React 19 + TypeScript + Vite 6, маршрутизация реализована в `src/main.tsx`.
- Интерактивные компоненты: Three.js и собственные React/TypeScript-компоненты.
- Публикация: GitHub Actions собирает frontend; `nginx.conf` раздаёт SPA и статические игровые сборки.
- Игры не используют один движок, и это правильно: каждый формат подключается своим способом, без массового переписывания.

## 2. Обнаруженные игры и способы запуска

| Игра | Путь из исходников | Технология/способ |
|---|---|---|
| Империя времени | `src/TimePrototype.tsx`, маршрут `/games/time` | React/TypeScript |
| SWARM | `public/games/swarm/index.html` и соседние файлы | Отдельная браузерная HTML/JS-игра |
| NULL//SHIFT | `godot/null-shift` и `public/games/null-shift/` | Godot Web export готовится в CI; есть WebGL-запасная версия |
| INHERIT | `public/games/inherit/index.html` | Отдельная браузерная игра |
| REMIX | `public/games/remix/index.html`, `public/games/remix/player/Build/` | Оболочка Unity WebGL |

Браузерные ресурсы доступны в репозитории; это не доказывает, что каждый production-маршрут или каждый внешний адрес отвечает из текущей среды. Проверка действующего сайта через доступный браузерный инструмент завершилась «Cache miss», а DNS-запросы из контейнера недоступны. Поэтому статусы live URL не отмечены как подтверждённые. Это ограничение среды, а не доказательство недоступности сайтов.

## 3. Что меняет OSGARD PLAY

- Добавляется единая премиальная игровая витрина на `/games`, сохраняя существующие URL.
- Каталог использует `src/core/manifest.ts` как источник списка игр.
- Поиск, фильтры по жанрам, сортировка, локальное избранное и история реализуются на клиенте.
- Отдельная страница `/games/play/:id` предоставляет игровую область, полноэкранный режим, повторный запуск, прямое открытие, статус загрузки, резервный путь для NULL//SHIFT и релевантные переходы к другим играм.
- Кросс-промо использует ссылки с UTM-метками. UTM помогает разделять источники, только если целевой продукт/аналитика действительно читает эти параметры.
- Форма заказа открывает почтовый клиент и не отправляет личные данные на сервер. Для полноценной CRM-формы потребуется серверная конечная точка, защита от спама и политика хранения заявок.
- Настройки необязательной продуктовой аналитики применяются к событиям игровой витрины. Это не универсальный баннер согласия для всего старого сайта.

## 4. Бренд и доступность

Используется существующая в репозитории оригинальная SVG-эмблема `public/osgard-mark.svg`. Оформление построено на обсидиановой основе, графитовых поверхностях, холодных синих тонах и приглушённом золотом акценте. Управление поддерживает клавиатурный фокус, есть адаптивные состояния, состояния загрузки/ошибки и режим `prefers-reduced-motion`.

## 5. Монетизация: текущее положение

На витрине есть честно обозначенная точка обращения за спонсорской интеграцией. Подключённой рекламной сети, подтверждённого rewarded-video, серверной оплаты, платёжной проверки и админ-панели монетизации в этой итерации нет. Они требуют выбранного поставщика, аккаунта издателя, серверного API и секретов в серверном хранилище. Нельзя объявлять эти интеграции действующими до настройки и теста.

Клиентское избранное и история — пользовательские настройки, а не аккаунтная облачная синхронизация. События отправляются через существующую очередь OSGARD с согласием для необязательной продуктовой аналитики; серверная синхронизация зависит от существующей авторизации и состояния API. Отдельной административной панели с фактическими метриками пока нет.

В репозитории домашней страницы встречается другой домен `osgardnewworld.com`; он не подменяет домен `osgardbewworld.com`, предоставленный владельцем для игровой витрины.

## 7. Запуск, QA и публикация

Локально:
```sh
npm ci
npm run check
npm run build
npm run qa:games
```

Production-маршруты проверяются отдельной командой `npm run qa:production-routes` при доступном сайте. Точный статус внешних маршрутов нужно повторно проверить после публикации. CI должен пройти типизацию, production build, игровые smoke-тесты и матрицу маршрутов до объявления релиза.

Изменения в feature-ветке не меняют опубликованный сайт до слияния. После review — открыть PR в `master`, дождаться green CI, слить согласно принятому процессу и подтвердить итоговый deploy вместе с production route matrix.
