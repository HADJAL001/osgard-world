# OSGARD SELECT, SHARDS и рост игрового портала
**Дата:** 13 октября 2026  
**Статус:** код готовится к CI; рекламные SDK и платежи не активируются этим изменением.

## Межигровой экран

После подтверждённого завершения раунда или закрытия действительно запущенной игровой сессии каталог предлагает OSGARD SELECT. Это самореклама собственных проектов OSGARD, а не сторонняя рекламная сеть. Переход добровольный; игроку доступны кнопки перехода, возврата к каталогу и приглашения друга.

По умолчанию собственные сервисы предлагаются после каждой завершённой сессии. В «Настроить показ» игрок может:
- выбрать конкретные продукты, которые ему интересны;
- восстановить все доступные продукты или убрать все;
- оставить показ после каждой завершённой сессии, сократить его до одного раза на три завершённых раунда или полностью выключить.

Настройки и счётчик завершённых раундов сохраняются локально в браузере. Они не отправляются на сервер. Если выбрано «выключить», сервисные карточки скрываются, но игра, возврат к каталогу и приглашение друга остаются доступны.

В системе десять записей сервисов, девять готовы к переходу. GARD VPN остаётся неактивным в рекламе до подтверждения доступности, но отображается как недоступный, а не как рабочее предложение. Активные ссылки содержат `utm_source=osgard_games`, `utm_medium=post_game`, `utm_campaign=after_game` и `utm_content=<service>_<game>`.

## Измерение переходов без фиктивных показов

Событие `cross_promo_clicked` отправляется только при клике по реальной активной ссылке и только если пользователь включил необязательную аналитику. Запрос использует настроенный Commerce API через `/games/commerce-config.json`. Никакое событие «показ рекламы» не создаётся при рендере карточки. UTM-метки помогают сервису назначения определить источник перехода; они сами по себе не доказывают регистрацию, покупку или доход.

## Приглашения и SHARDS

У OSGARD SELECT есть ссылки-вызовы на конкретную игру, кнопки для Telegram, WhatsApp, VK, X и Facebook, а также системное меню отправки или копирования ссылки. В SIGNAL RUN баланс SHARDS виден прямо на игровом экране и синхронизируется с тем же локальным кошельком, который использует межигровой экран.

За успешно завершённое действие отправки через системное меню либо копирование ссылки выдаётся +50 SHARDS не чаще одного раза за UTC-сутки на текущем браузере/устройстве. Для кнопок соцсетей игрок может вернуться на сайт и сам подтвердить публикацию. Ни сайт, ни обычная Web Share API не получают надёжного подтверждения, что публичный пост действительно опубликован: отмена системного меню награду не даёт. SHARDS — локальные демонстрационные очки, не деньги, не серверный баланс и не право на покупку. Их нельзя представлять как денежную ценность, платёжное средство или доказательство реального репоста.

Это ограниченная клиентская механика для проверки интереса, не защита от намеренной подделки localStorage. Если в будущем SHARDS станут переносимыми между устройствами или будут обмениваться на реальные преимущества/товары, потребуется серверный журнал транзакций, проверка прав и защита от повторного начисления.

## Бизнес-модель и цель $1 млн

$1 млн — целевой сценарий, не обещание дохода. Монетизацию следует считать отдельно по проверенным источникам:

- **Собственные сервисы:** клики с каталога → подтверждённые действия на сайте назначения → реальная конверсия. Сейчас настроены UTM и согласованные клики, но не подключена общая серверная отчётность всех десяти доменов.
- **Заказная разработка:** заявки с сайта OSGARD → квалифицированные лиды → подписанные договоры и фактически полученные платежи. Не считать отправку формы или потенциальный контракт полученным доходом.
- **Платная реклама и спонсорство:** включать только после подключения провайдера/договора, проверки маркировки, региона и правил согласия. В этой реализации сторонний рекламный SDK и платные размещения не включены.
- **Покупки и Premium:** не включать в выручку, пока нет checkout, серверной проверки оплаты, вебхуков, возвратов и серверных прав доступа.

Формула для планирования:  
`годовая выручка = подтверждённые рекламные выплаты + полученные платежи от покупателей + полученные платежи по договорам разработки + фактические спонсорские платежи`.

Отдельно следить за игровым воронкой: приглашения созданы → переходы по реферальным ссылкам → новые игровые старты → завершённые сессии → повторные игры. Коэффициент вирусности рассчитывать по наблюдаемым данным, а не по числу нажатий «Поделиться»:  
`K = среднее число отправленных приглашений на игрока × доля приглашений, по которым открылся сайт × доля приглашённых, начавших игру`.  
Успешно открытое share-меню — это действие пользователя, но не подтверждение доставки, уникального получателя, покупки или дохода.

Сценарная модель и её допущения остаются в `docs/GAMES_MONETIZATION_MODEL.md`. Демонстрационные значения должны быть заменены фактическими источниками с указанным периодом измерения, прежде чем использоваться для управленческих решений.
