# OSGARD PLAY — Product Experiment Engine
Дата: 14 октября 2026 г.
Ветка: feat/osgard-consented-product-experiments-2026-10-14

## Зачем
OSGARD PLAY уже имеет каталог, Player Console, рекомендации, согласие на аналитику и Commerce Admin. Следующий слой — замкнутый цикл продуктового улучшения: проверять гипотезу, измерять цель и не объявлять победителя без данных.

## Реализовано
- A/B-тест catalog-hero-cta-v1: контроль «Исследовать игры» и вариант «Найти свой игровой мир».
- Назначение варианта работает только после явного согласия. Без согласия показывается контроль; назначения не сохраняются и события не отправляются.
- Вариант хранится только в sessionStorage текущей вкладки/сеанса. Новые cookies, сторонние SDK и персональные идентификаторы не добавляются.
- Экспозиция учитывается, когда кнопка видна в окне не менее 900 мс; цель — клик по кнопке.
- События передаются только через существующую очередь OSGARD_CONSENTED_ANALYTICS. Сервер строго проверяет ID эксперимента, вариант и соответствие фазы имени события.
- Commerce Admin получает сводку за 30 дней: показы-сеансы, цели, CR A/B, разницу в процентных пунктах и приблизительный 95% интервал.
- Сигнал не показывается, пока не накоплено минимум 200 сеансов с показом на каждый вариант; автоматического выбора победителя нет.

## Ограничения
- Единица подсчёта — сеанс с подтверждённой видимостью, а не уникальный человек.
- Это один тест текста CTA, не доказательство роста выручки, удержания или прибыли.
- Интервал — приблизительный диагностический сигнал; коммерческое решение требует заранее заданного горизонта и повторной проверки.
- Клиентские события могут быть подделаны. Они не влияют на деньги, награды или доступ.
- При неработающем API/базе отчёт остаётся пустым, без выдуманных демонстрационных цифр.

## Проверки и публикация
- Проверка: npm run qa:product-experiments
- API unit tests: cd services/osgard-commerce-api && npm test
- Games Growth PR workflow запускает новый smoke test вместе с TypeScript, существующими контрактами игр и production build.
- Для серверного отчёта нужны существующие Commerce API и PostgreSQL. Новых клиентских ключей не требуется.
- После прохождения CI проверить реальные согласованные события в /games/commerce-admin/. Автоматический выбор варианта не включён.
