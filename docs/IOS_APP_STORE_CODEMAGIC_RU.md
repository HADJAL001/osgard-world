# OSGARD PLAY — подготовка к iOS / App Store

**Цель первого этапа:** получить подписанную IPA и загрузить её в TestFlight через Codemagic. Публичная отправка на App Review отключена намеренно.

## Почему отдельное OSGARD PLAY, а не весь OSGARD WORLD

Мобильный бинарник открывает локально упакованный каталог игр, а не удалённую копию главного сайта. Игровые HTML/CSS/JS-страницы собираются в `dist`; для iOS отдельная стартовая страница открывает `/games/`. Рекламные и аналитические данные не добавляются в приложение автоматически. Кнопка системного шаринга подключается через Capacitor Share.

Это лучше, чем указывать `server.url=https://osgard.world` и делать из приложения простой WebView сайта. Но одобрение Apple не гарантируется: перед публикацией нужно проверить, что игровой опыт достаточно самостоятельный и не превращается в витрину собственных сервисов. Apple отдельно проверяет минимальную функциональность, маркетинговые/ссылочные приложения и встроенные HTML5-игры. Смотри актуальные [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/).

## Что уже подготовлено в коде

- `capacitor.config.json` — Bundle ID-кандидат `com.osgardworld.play`, название OSGARD PLAY и локальный каталог `dist`.
- `mobile/vite.config.mjs` и `mobile/capacitor-share-bridge.js` — отдельный JS-бандл для нативного окна отправки iOS.
- `scripts/prepare-ios-app.mjs` — создаёт стартовую страницу приложения, настраивает URL собственного API для нативного origin, предотвращает неработающий Godot URL в iOS-каталоге, подготавливает Xcode-проект и иконки.
- `mobile/PrivacyInfo.xcprivacy` — декларация privacy manifest для взаимодействий с играми и идентификатора пользователя. Её нужно сверить с реальными потоками данных до релиза.
- `codemagic.yaml` — подписанная сборка IPA и загрузка в TestFlight. Публичная отправка на App Store Review не включена.
- `scripts/ios-appstore-preflight.mjs` — проверка конфигурации, локальных игровых маршрутов, privacy manifest и созданного мобильного bundle.

**Нельзя считать готовым без реальной сборки на Codemagic:** сертификат, provisioning profile, IPA, работу на iPhone/iPad, скриншоты App Store и решение Apple.

## 1. Apple Developer и App Store Connect

1. Нужна активная учётная запись Apple Developer Program. Apple указывает ежегодный взнос **99 USD** (местная цена и валюта отображаются при регистрации): [официальная страница](https://developer.apple.com/help/account/membership/program-enrollment/).
2. В App Store Connect создай приложение **OSGARD PLAY**, язык карточки — русский, SKU — `osgard-play-ios-001`.
3. Зарегистрируй Bundle ID `com.osgardworld.play` в Apple Developer. Bundle ID должен быть свободен и должен точно совпадать с Xcode/Codemagic. Если он уже занят твоим приложением, согласованно измени его и в `capacitor.config.json`, и в `codemagic.yaml`.
4. Создай App Store Connect API key с ролью **App Manager**. Скачай файл `.p8` сразу: Apple позволяет скачать приватный ключ только один раз. Не добавляй его в Git.

## 2. Codemagic

1. Добавь репозиторий `HADJAL001/osgard-world` в Codemagic и дай ему доступ к ветке `master`.
2. В Team integrations → Developer Portal / App Store Connect keys загрузи API key, Issuer ID и Key ID. Назови integration **OSGARD_PLAY_ASC** — это имя используется в `codemagic.yaml`.
3. В Code signing identities настрой автоматическое создание/получение Apple Distribution certificate и App Store provisioning profile для `com.osgardworld.play`. В workflow указан `distribution_type: app_store`.
4. После настройки проверь обнаружение `codemagic.yaml`. Создай tag `osgard-play-v1.0.0`, чтобы запустить workflow; можно запускать из интерфейса Codemagic вручную, если для репозитория доступен ручной запуск.
5. Версия берётся из тега: `osgard-play-v1.2.3` → маркетинговая версия `1.2.3`. Используй только формат `X.Y.Z`; некорректный тег остановит сборку до установки зависимостей. Для ручной сборки без тега можно задать переменную `APP_VERSION`. Build number берётся из системной переменной Codemagic `BUILD_NUMBER`.
6. Успешный workflow должен прикрепить `.ipa` к сборке и загрузить её в TestFlight. Он **не** публикует приложение для всех пользователей.

## 3. Что обязательно проверить на реальном iPhone

- Первый запуск, возврат из фона, отсутствие интернета и повторное открытие.
- Каталог, сенсорное управление, полноэкранный режим, звук/ориентацию и выход из каждой игры.
- Все основные игровые экраны и все десять карточек каталога; NULL//SHIFT в iOS-сборке использует локально включённую WebGL-версию вместо отсутствующего в web-каталоге нативного Godot export.
- Нативное меню «Поделиться» — ссылка должна вести на `https://osgard.world/games/`, а не на локальный `capacitor://localhost`.
- Переходы к сторонним приложениям, WhatsApp и возврат обратно в игру.
- Аналитику только после согласия; отказ и отзыв согласия должны останавливать необязательную отправку событий.
- Игры с подключённым API: CORS production API должен допускать origin `capacitor://localhost`. Если Render/сервер использует явный `ALLOWED_ORIGINS`, добавь туда ровно этот origin после проверки приложения.
- Сообщение при недоступном API. Локальные игры не должны ломаться из-за отключённой аналитики.

## 4. App Store карточка — черновик

**Название:** OSGARD PLAY

**Подзаголовок:** Играй. Решай. Передавай вызов.

**Краткое описание:** Исследуй игровые миры OSGARD — от тактических задач и головоломок до стратегий. Запускай игру, сохраняй свои любимые миры и передавай друзьям ссылки на новые испытания.

**Ключевые слова (черновик):** игры, головоломки, стратегия, тактика, аркада, испытания, OSGARD

**Support URL:** `https://osgard.world/` (до отправки лучше создать отдельную страницу поддержки OSGARD PLAY).

**Privacy Policy URL:** `https://osgard.world/privacy/`

**Что ещё нужно подготовить вручную:** иконка уже генерируется при сборке; дополнительно нужны настоящие скриншоты приложения на поддерживаемых iPhone/iPad, точный возрастной рейтинг, контакт Review, описание доступа к сети и достоверные App Privacy Details. Проверь все игры и ассеты на права использования.

## 5. Важные правила перед App Review

- Не включай автоподачу на публичное ревью до реального smoke-тестирования и заполнения карточки.
- Внутриигровые цифровые товары/платные уровни/подписки не подключены этим workflow. Перед продажами цифрового контента в iOS нужно отдельно реализовать и проверить Apple In-App Purchase/StoreKit по правилам конкретного продукта.
- Продвижение собственных сайтов должно быть вторичным, явно рекламным и легко закрываться. Не превращай игровой процесс в последовательность обязательных промоэкранов.
- SHARDS описываются как виртуальные игровые очки без денежной стоимости. Кнопка «поделиться» не может достоверно подтвердить публичную публикацию в социальной сети — это нужно прозрачно обозначать и не обещать финансовую награду.
- Возрастной рейтинг заполняется по реальному содержанию всех игр. Перед релизом проверь, требуется ли механизм ограничения доступа к отдельным играм с более высоким рейтингом.
