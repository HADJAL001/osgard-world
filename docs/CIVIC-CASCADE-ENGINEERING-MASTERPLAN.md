# CIVIC CASCADE — инженерный мастер-план

**Статус документа:** инженерная стратегия и релизная политика.  
**Текущая базовая версия:** 2.8.0 — автономный локальный поиск штабных планов.  
**Продуктовая цель:** превратить CIVIC CASCADE из набора кризисных кнопок в объяснимую, проверяемую симуляцию принятия решений — без ложных обещаний об ИИ, физических моделях и живой телеметрии.

## 1. Архитектурный принцип

Состояние города — единственный источник истины. Реальные игровые действия, превью очереди, прогноз и автономный планировщик должны использовать одну и ту же модель эффектов. Планировщик никогда не изменяет рабочее состояние: он получает копию состояния, проверяет допустимость последовательности, моделирует последствия на горизонтах 30/60/90 игровых секунд и сравнивает результат с базовой траекторией без новых приказов.

Новая версия добавляет ограниченный deterministic beam search: глубина не больше четырёх команд, ширина фронта шесть кандидатов, ремонт рассматривается для трёх наиболее слабых узлов и выбранного оператором узла. Целевая функция выбирается явно: баланс города, снижение общего риска, защита инфраструктуры или экономия ресурсов. Планировщик показывает до трёх допустимых альтернатив; найденный план никогда не исполняется автоматически.

## 2. Принципы инженерного качества

1. **Никаких выдуманных прогнозов.** Прогноз включает только реализованные правила модели. Случайные будущие инциденты, не введённая погода и решения игрока не считаются известными.
2. **Одинаковая семантика исполнения и симуляции.** Каждый новый эффект действия обязан иметь парный регрессионный тест против живого действия.
3. **Ограниченная сложность.** У поиска есть жёсткие глубина, ширина и лимит команд; пользователь видит цель оптимизации и измеряемые последствия.
4. **Нет скрытой передачи данных.** В релизе 2.8.0 поиск выполняется локально. Сохранения и результаты не отправляются автоматически на сервер.
5. **Безопасное использование моделей.** Ключи OpenAI никогда не кладутся в HTML, JavaScript, Git или публичный конфиг. Подключение реальной модели допустимо только через защищённый серверный шлюз с лимитами расходов, строгой схемой вывода и журналом ошибок без персональных данных.
6. **Постепенная деградация.** Если браузер не поддерживает видеоэкспорт или тяжёлую функцию, базовый игровой цикл остаётся работоспособным.
7. **Проверяемая публикация.** Commit, прохождение тестов и открытая production-страница — три разных сигнала; ни один нельзя подменять другим.

## 3. Версия 2.8.0 — локальный автономный штаб

### Входит в релиз
- Поиск допустимых очередей длиной 1–4 приказа с оценкой каскадов на T+30/T+60/T+90.
- Четыре функции цели с разными весами: **balanced**, **risk**, **protect**, **conserve**.
- Проверка доступного бюджета и числа бригад при оценке каждой последовательности.
- До трёх ранжированных вариантов с показателями риска, слабейшего узла, затрат и критических узлов.
- Явное применение: выбрать кандидат → загрузить в очередь → проверить → самостоятельно нажать исполнение.
- Инвалидация результата, когда изменилось состояние симуляции.
- Детерминированные регрессионные тесты для границ поиска, бюджетов, бригад, неизменности исходного состояния и повторяемости результата.

### Критерии приёмки
- Все метрики прогноза конечны и ограничены допустимыми диапазонами.
- Каждый предложенный план допустим по текущим ресурсам и бригадам.
- Поиск не меняет игровое состояние и выдаёт тот же результат при повторном запуске на том же состоянии.
- Планировщик не запускается в неустойчивом состоянии, требует паузы и не исполняет команды сам.
- Количество исследуемых комбинаций остаётся ограниченным верхним пределом; интерфейс остаётся пригодным для мобильного экрана.
- В манифесте релиза, UI-версиях и smoke-тесте совпадает номер сборки.

## 4. Следующие этапы

### Этап A — конвейер качества
- Проверять синтаксис встроенного JavaScript, JSON манифеста, уникальность HTML ID и все readiness-маркеры.
- Запускать regression smoke на каждый pull request.
- Проверять production route matrix после публикации, фиксируя HTTP-статусы, версию релиза и время ответа.
- Считать публикацию подтверждённой только после проверки публичного маршрута и версии снаружи.

**Gate:** тесты и route matrix проходят; нет секретов в артефактах; релизная версия совпадает во всех контрактах.

### Этап B — достоверность модели
- Добавить тесты на каждый порог каскада и на границы устойчивости узлов.
- Сравнивать прямые прогнозы с фактически применёнными действиями в контролируемых сценариях.
- Для каждой метрики показывать источник изменения: действие, связь инфраструктуры или реализованное правило симуляции.
- Не добавлять случайность в прогноз без воспроизводимого seed и отдельного описания неопределённости.

**Gate:** детерминированные тесты повторяются локально и в CI; необъяснённые расхождения запрещают релиз.

### Этап C — replay и сценарная лаборатория
- Сформировать воспроизводимые сценарии с seed и версией модели.
- Сохранять компактный локальный журнал действий и контрольные снимки, с экспортом только по явному действию пользователя.
- Добавить сравнение двух стратегий на одинаковом стартовом состоянии.
- Отдельно измерять обучение игрока: понимает ли он причины системных отказов, а не только набирает баллы.

**Gate:** воспроизводимость сценария подтверждена тестом; экспорт очищен от случайных и идентифицирующих данных.

### Этап D — опциональный OpenAI Advisor
- Оставить детерминированный движок источником истины для бюджета, симуляции и последствий.
- Поднять серверный endpoint с аутентификацией/ограничением частоты и бюджетом на пользователя или сессию.
- Хранить API-ключи только в серверных secrets; запретить передачу ключей на клиент.
- Передавать модели минимальный структурированный снимок состояния без личных данных.
- Требовать JSON по строгой схеме: гипотеза, причины, возможные действия, неизвестные факторы и предупреждения.
- Проверять все предложенные действия детерминированным симулятором до отображения пользователю. Модель не может самостоятельно исполнять команды.
- Иметь выключатель функции, лимиты токенов и стоимости, тайм-аут, отказобезопасный локальный режим и тесты prompt injection.

**Gate:** модель улучшает решения в слепом сравнении с локальным поиском; стоимость и задержка измерены; секреты и пользовательские данные защищены. Пока gate не пройден, нельзя маркировать игру как использующую OpenAI API.

### Этап E — производительность и выпуск
- Проверить настольный Chrome/Edge, мобильный Safari и Android Chromium на реальных устройствах.
- Измерить время поиска на типовых и стрессовых состояниях; задать бюджет времени для слабого телефона.
- При превышении бюджета уменьшить ширину поиска или выполнять его по частям, не замораживая интерфейс.
- Проверить клавиатурный фокус, экранные дикторы, уменьшение анимации, касания и длинные тексты на узком экране.
- Развёртывать сначала по опубликованному manifest, затем подтверждать версию внешней проверкой.

**Gate:** нет блокирующих ошибок, превышения согласованного времени отклика и расхождений между заявленной и фактической версией.

## 5. Система метрик

Измерять локально в тестах: время расчёта, количество рассмотренных допустимых планов, долю состояний без улучшения, улучшение риска на T+90, сохранность слабейшего узла, расход ресурсов, долю планов, отвергнутых валидатором, ошибки и отклонения реального результата от прогноза.

В продуктовой аналитике считать только добровольно предоставленные, агрегированные события. Не собирать содержимое сохранений, личные сведения или состояние города без явного согласия. Не называть открытие страницы, ссылку челленджа или показ варианта подтверждением реального пользователя, публикации либо конверсии.

## 6. Релизная дисциплина

Для каждого выпуска обязательны: изменённый контракт релиза, smoke-тест, проверка совместимости сохранений, краткие release notes, фиксация commit SHA и внешняя проверка production-версии. Если CI не запускался, пишется «CI не подтверждён». Если публичный маршрут недоступен проверочному инструменту, пишется «production не подтверждён». Никаких фиктивных процентов покрытия, бенчмарков или заявлений о 8K-рендеринге, если фактически использовано масштабирование.

## 7. Текущая позиция

Версия 2.8.0 добавляет объяснимый локальный поиск штабных решений поверх уже существующих сетевых зависимостей, прогнозов, кризисных инцидентов и послеоперационного разбора. Реальный OpenAI Advisor, сетевой рейтинг и серверная аналитика остаются отдельными архитектурными этапами, а не скрыто включёнными обещаниями.
