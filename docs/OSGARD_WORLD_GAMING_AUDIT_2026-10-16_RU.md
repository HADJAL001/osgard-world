## Результат аудита

Это не пустой проект и не статический макет. В исходном репозитории уже обнаружены React 19, TypeScript и Vite; отдельные игровые сборки лежат в public/games/, а Commerce API вынесен в services/osgard-commerce-api/ и использует Express, PostgreSQL и Stripe. Каталог резервного запуска — public/games/game-catalog-fallback.json; на момент проверки в нём 12 игр. Статусы playable и prototype различаются явно.

Существующие системы, которые сохранены и проходят через release preflight:
- Премиальная игровая витрина, поиск/фильтры, карточки и страницы игр.
- 12 записей каталога, runtime-каталог и lifecycle-события игровых iframe.
- Каталог собственных проектов /games/ecosystem/, интеграции партнёров и игровые рекомендации.
- Интерфейсы монетизации/финансовой модели, каталог-редактор, менеджер кампаний и партнёрский раздел.
- Consent-aware analytics, центр доступности, диагностика маршрутов, коммерческий API и QA-контракты.
- Отдельные игровые сборки и service worker там, где поддерживается PWA/offline.

## Пять крупных блоков этой поставки

### Блок 1 — проверка продукта перед выпуском
Создан scripts/osgard-full-release-preflight.mjs. Он проверяет существование ключевых страниц и API, структуру каталога, уникальность game ID, допустимые статусы, безопасные same-origin URL и отсутствие отслеживаемых файлов окружения/приватных ключей в source bundle.

### Блок 2 — полный архив исходников
Создан scripts/osgard-full-release-bundle.mjs. Он формирует source ZIP из полного tracked snapshot Git-коммита через git archive. В архив не попадают .git, node_modules, локальные untracked файлы и локальный dist; данные окружения дополнительно проверяются до упаковки.

### Блок 3 — отдельно собираемый production-сайт
Тот же упаковщик создаёт отдельный ZIP из свежесобранной папки dist/. Это даёт разработчику два разных артефакта: полный исходный проект и готовые статические файлы frontend.

### Блок 4 — целостность и происхождение
В пакет включаются bundle-manifest.json с версией, SHA коммита, временем сборки, количеством файлов и SHA-256 обоих ZIP, а также SHA256SUMS.txt. Оба ZIP тестируются командой unzip -t до публикации artifact.

### Блок 5 — автоматизированный release workflow
Добавлен .github/workflows/osgard-full-release-bundle.yml: установка зафиксированных зависимостей, preflight, production build, QA каталога, тесты экосистемы/consent/финансовой модели, генерация и загрузка artifact. Это запускается в отдельной ветке; master и production сайт этим изменением не перезаписываются.

## Важные границы

- Этот пакет не доказывает, что изменения уже развернуты на https://osgard.world.
- Ответ внешнего URL не доказывает полную функциональность проекта. Существующий health-check внешних проектов проверяет только доступность homepage/часть видимых метаданных.
- Реклама считается неактивной, если нет одобренной рекламной сети, согласия там, где требуется, и проверенных размещений. Показы/клики не имитируются.
- Наличие Stripe-кода не означает, что реальные платежи готовы к продаже. Нужны production secrets, webhook verification, проверка entitlements, отмен/возвратов и налогово-правовой контур.
- Dashboard/операторские маршруты не становятся защищёнными только от noindex; запись должна оставаться за серверной аутентификацией.
- Прогноз финансов — допущения модели, не реальная выручка.
- Ветка и ZIP требуют успешного CI review; данный workflow не публикует сайт автоматически.

## Статус проверки в этой ветке

Скрипты bundle-preflight и package workflow добавлены; окончательный статус будет виден в GitHub Actions artifact после выполнения workflow. Не следует считать ZIP проверенным до зелёного результата workflow и доступного bundle-manifest.json.
