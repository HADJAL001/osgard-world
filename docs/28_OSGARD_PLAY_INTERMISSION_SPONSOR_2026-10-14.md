# OSGARD PLAY — послеигровые спонсорские предложения и единое согласие

Дата: 14 октября 2026 года  
Ветка: `feat/osgard-play-intermission-sponsor-20261014`

## Что изменено

- Добавлена отдельная точка показа `after_session` на странице игры: она появляется только после явного закрытия игрового окна, а не перекрывает игровой процесс.
- Коммерческий API допускает активные кампании в каталоге (до 3 одновременно) и на экране между сессиями (до 1). `game_event` остаётся заблокированным до отдельной проверки точек интеграции.
- Слот отображает явную маркировку «Реклама», «Партнёрский материал» или «Спонсорский материал». Содержимое вставляется как текст, URL должен пройти проверку HTTPS и не может содержать учётные данные, query или fragment.
- Показ считается только после не менее 1 секунды фактической видимости 50% карточки. В событие передаётся идентификатор кампании и игры; UTM-параметры добавляются к переходу.
- Необязательные события и локальный 24-часовой frequency cap включаются только при согласии `yes`. Без согласия предложение может отображаться, но не ведётся сохранённый лимит или аналитика. Если локальное хранилище недоступно при согласии, слот скрывается.
- Страница игры теперь читает и пишет то же значение согласия `yes/no`, которое использует общий аналитический мост. Старые `granted/denied` мигрируются в `yes/no`, чтобы не ломать выбор пользователя.
- Если Commerce API не настроен, база не готова или нет действующей кампании, предложение не показывается. `public/games/commerce-config.json` остаётся пустым по умолчанию: фейковые кампании и показы не создаются.

## Проверки

- `npm run qa:intermission-sponsor`
- `npm run qa:campaign-manager`
- `node --test services/osgard-commerce-api/test/campaigns.test.mjs`
- `npm run check`
- `npm run build`

Интеграция не включает стороннюю рекламную сеть и не включает платежи. Реальные показы и клики в операторской сводке появятся только после настройки Commerce API, включённой аналитики пользователя и фактической видимости/переходов. На production после слияния PR отдельно нужно проверить мобильный экран после закрытия игры, endpoint `/v1/campaigns/active?placement=after_session` и лимиты базы.
