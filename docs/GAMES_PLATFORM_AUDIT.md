# OSGARD WORLD GAMES — технический аудит и состояние внедрения
Дата аудита: 13 октября 2026 года  
Репозиторий: `HADJAL001/osgard-world`  
Рабочая ветка: `feat/osgard-games-hub-2026-10`

## 1. Что обнаружено в репозитории

Существующий проект — веб-портал на React 19, TypeScript и Vite 6. В корневом `package.json` уже есть проверки TypeScript, production build, проверка маршрутов, аудит архивов и smoke-тесты ряда игровых сценариев. Поэтому весь сайт не переносится на Godot/Unity: браузерная витрина должна оставаться в существующем web-стеке, а игры продолжают использовать собственные технологии.

Игры и точки входа, найденные в исходниках:
- **Империя времени** — React/TypeScript, маршрут `/games/time`, исходный компонент `src/TimePrototype.tsx`.
- **SWARM** — статическая HTML/Canvas/JavaScript-сборка в `public/games/swarm/`; содержит управление клавиатурой, сенсорные кнопки, настройку роли и сетевой интерфейс комнат.
- **NULL//SHIFT** — существующая браузерная Canvas/WebGL-сборка в `public/games/null-shift/`, с `game.js`, `engine-3d.js`, CSS и сенсорным интерфейсом. В репозитории также лежит исходный Godot-проект, но отдельный опубликованный `index.wasm/index.pck` экспорт не подтверждён в отслеживаемых файлах. Старый каталог ссылался на неподтверждённый `/games/null-shift-godot/index.html`; новая витрина указывает на существующую browser build.
- **INHERIT** — самостоятельная HTML/JavaScript-игра в `public/games/inherit/`.
- **REMIX** — HTML-страница, запускающая Unity WebGL-сборку; готовность WebGL зависит от загрузки её ресурсов и возможностей устройства.

В репозитории уже была страница Entertainment, дублировавшая часть каталога, и разные игровые CTA. Отдельная production route matrix покрывала игровые маршруты, но не новый корневой маршрут `/games`.

## 2. Что внесено в ветку

### Новая игровая витрина
- Добавлен `public/games/index.html`, обслуживаемый как самостоятельная страница `/games`, с премиальным графитовым оформлением, золотыми/бирюзовыми акцентами, адаптивной сеткой, фирменной эмблемой, поиском, фильтрами, избранным и продолжением последней открытой игры.
- Добавлен внешний `public/games/hub.css`; анимации учитывают `prefers-reduced-motion`. Удалён запрос Google Fonts: страница использует локальные системные fallback-шрифты и не требует стороннего обращения ради загрузки шрифта.
- Добавлен `public/games/hub.js` — каталожная логика, карточки деталей, загрузочная оболочка игры, открытие отдельно, fullscreen, поиск, фильтрация, share API/clipboard fallback, local history/favorites, состояние ошибок и переключение RU/EN.
- Добавлен `public/games/catalog.json` с пятью фактическими точками входа и десятью направлениями экосистемы. В каталоге нет выдуманных рейтингов, числа игроков, отзывов, live-статистики или финансовых показателей.
- Добавлен `public/osgard-mark.svg`; основной favicon сайта переведён с JPEG-обложки на отдельную оригинальную SVG-эмблему.
- Добавлена `public/games/privacy.html` с уведомлением о локальном хранении, согласии на необязательную аналитику, внешних играх и текущем отсутствии платежей/рекламной сети.
- Добавлена legacy-переадресация `/entertainment` на `/games`, чтобы не ломать старую ссылку.
- Ссылки NULL//SHIFT в React manifest и homepage Play Gateway исправлены на отслеживаемую браузерную сборку.
- Публичная sitemap дополнена Games hub и пятью точками входа.
- Добавлен `scripts/games-platform-smoke.mjs`; новая команда `npm run qa:games` включена в release readiness.
- Расширен `docs/RELEASE_QA_CHECKLIST.md` для проверки каталога, мобильных экранов, аналитики и ошибок загрузки.

### Аналитика
- Выключена по умолчанию и требует явного переключателя.
- В локальном журнале хранятся не более 300 событий. События не содержат поисковую фразу или поля контактной формы.
- Если пользователь согласился и уже авторизован в OSGARD (имеет токен, который использует существующая авторизация), разрешённые события могут отправляться только на same-origin `/api/v1/player/events`. Очередь повторяет отправку при восстановлении сети. Используются только имена событий из текущего контракта OSGARD.
- Без согласия события не записываются в аналитический журнал и не отправляются. Избранное и история запуска хранятся локально как функциональные данные.
- Экспорт событий доступен как локальный JSON. Платформенная admin dashboard ещё не реализована.

### Контакт и заявки
- Добавлены email и WhatsApp, CTA для заказа разработки и формы brief.
- Форма готовит письмо через `mailto:`. Она **не** заявляет об успешной серверной отправке и не размещает контактные данные в игровых ассетах или логах.

## 3. Что пока не реализовано

- Платёжный провайдер, покупки, возвраты, подписка OSGARD PREMIUM, права доступа на сервере и внутриигровая валюта.
- Рекламная сеть, rewarded video, реальный ad fill/eCPM, оплачиваемые sponsor placements. На странице размещён только прозрачный запрос на обсуждение спонсорства; он не маскируется под рекламу.
- Защищённая admin dashboard для каталога, размещений, кампаний и финансовых отчётов.
- Серверная агрегированная продуктовая аналитика и dashboard метрик. Текущая версия синхронизирует только разрешённые события уже авторизованных игроков через существующий API, если backend принимает этот контракт.
- Реальная проверка запуска Unity WebGL/игрового движка на конкретном браузере из родительской страницы. Событие `iframe load` означает загрузку страницы, а не обязательно начало игровой сессии.
- Проверенный релиз Godot Web export для NULL//SHIFT. Ссылка на старый не подтверждённый экспорт удалена из игровых CTA.
- Фактическое опубликование на production. Доступ к deploy secrets/хостингу и успешный production check не подтверждены; изменения остаются в отдельной feature branch до review/merge/deploy.

## 4. Состояние проверки внешних ресурсов

Были предприняты запросы к `osgard.world` и десяти доменам экосистемы. В текущей исследовательской среде web-запросы возвращали cache/fetch errors или пустой поисковый результат. Поэтому live-доступность доменов, их текущие функции, коммерческие метрики и HTTP-статусы **не подтверждены**. Карточки используют названия, URL и краткие описания из брифа владельца; это не утверждение о проверенной доступности каждого сайта.

## 5. Как проверить в репозитории

Из корня проекта:
```bash
npm run qa:games
npm run check
npm run build
npm run preflight:frontend
npm run qa:production-routes
```

Для полного release gate:
```bash
npm run qa:release
```

Проверки production routes требуют доступного сайта и/или настроенного `OSGARD_BASE_URL`. Публикация в production должна оставаться отдельным контролируемым этапом, поскольку deployment pipeline ожидает secrets сервера.

## 6. Коммерческий следующий шаг

Сначала проверить, что каталог и все пять игровых страниц запускаются на реальном staging на desktop/mobile, а затем измерить посещения → открытия игры → реальное завершение игрового цикла. Только после этого выбирать сеть и модель монетизации. Без этих данных нельзя обоснованно выбрать eCPM, цену, конверсию, подписку или бюджет.
