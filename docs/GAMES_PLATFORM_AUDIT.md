## 1. Обнаруженная архитектура

Репозиторий уже содержит рабочий React 19 + Vite 6 + TypeScript-портал. Статические игровые файлы находятся в public/games/; SPA-маршрут игры «Империя времени» реализован в src/TimePrototype.tsx и маршрутизаторе src/main.tsx. Есть общая локальная очередь событий src/core/eventQueue.ts, API профилей/сессий и существующий набор CI-проверок.

| Игра | Точка входа | Фактическая интеграция |
|---|---|---|
| Империя времени | /games/time | React SPA, клиентский маршрут |
| SWARM | /games/swarm/ | Статическая браузерная игра; многопользовательская серверная часть описана в инфраструктуре |
| NULL//SHIFT | /games/null-shift/ | Самостоятельная браузерная игра: WebGL 3D + резервный Canvas |
| INHERIT | /games/inherit/ | Статическая браузерная игра, локальная история |
| REMIX | /games/remix/ | Unity WebGL build; требует подходящего браузера и достаточной памяти |

godot/null-shift/ содержит исходный Godot-проект и CI-инструкции для headless-проверки/экспорта. На момент аудита готовая экспортированная Godot-сборка не хранилась в public/games/null-shift-godot/ в исходном дереве ветки. Размещение Godot-сборки зависит от шага CI; поэтому основная кнопка запуска использует реально присутствующую браузерную версию, а переход к Godot не должен быть единственным способом открыть игру.

## 4. Аналитика и конфиденциальность

Новая витрина может записывать локальные события только после согласия пользователя: просмотр каталога, поиск/фильтр, игровое досье/запуск, продолжительность открытой сессии, избранное, запрос полноэкранного режима, исходящий кросс-промо-переход и создание черновика заявки. Текущий журнал ограничен 1 000 локальными событиями и экспортируется в CSV.

Это **не серверная бизнес-аналитика**: события не выгружаются в центральное хранилище, нет подтверждённых данных о посещениях, удержании, выручке, рекламных RPM/eCPM или конверсии. Игровые серверные события в существующих продуктах — отдельный контур и требуют соответствующей авторизации/API.

## 5. Что пока не готово к production

1. Изменения находятся в feature-ветке, не в production; перед слиянием нужен зелёный CI и review. После слияния публикация выполняется существующим безопасным процессом из DEPLOYMENT.md/ручного deploy workflow.
2. Внешние домены экосистемы не были подтверждены автоматической проверкой в этой среде; наличие ссылки не означает, что целевой сайт доступен или конвертирует.
3. Нет подключённой рекламной сети, платёжного аккаунта, серверной системы для рекламных подтверждений/покупок, central analytics sink или админки. Такие интеграции нельзя безопасно «включить» лишь статическим HTML.
4. Тексты privacy/terms — рабочие технические черновики. Нужно определить юридического оператора, применимое право, адрес обработки запросов, реальный срок хранения серверных логов и проверить требования к возрасту/согласию.
5. Для профессиональной оценки рекламы нужна реальная аудитория. Экономическая модель отдельно документирует предположения; она не является прогнозом фактического дохода.
6. Совместимость Unity WebGL на мобильных устройствах зависит от браузера и памяти; в досье это не скрыто. Требуется реальный тест на целевых устройствах.
7. Для UI интерактивного каталога нужен браузерный E2E-прогон на десктопе и телефоне помимо source-level smoke checks.
