# OSGARD PLAY — подготовка App Store через Codemagic

Статус: конфигурация сборки подготовлена в ветке feat/osgard-play-ios-codemagic-release. IPA не считается собранным, пока Codemagic не выполнит workflow с реальными сертификатами и подключением Apple.

## Выбранный путь

Используется **Capacitor 8 + локальная упаковка игр + Codemagic на macOS**. Это не ссылка на удалённый сайт внутри пустого WebView: в мобильный пакет копируются собранные веб-ресурсы, каталог и игровые страницы. Приложение стартует с /games/; для нативной среды подключён системный iOS Share Sheet, а ссылки capacitor://localhost/... при публикации превращаются в публичные URL https://osgard.world/....

Time — особый маршрут сайта, поэтому в мобильном пакете создаётся локальная точка входа /games/time/index.html. Godot-экспорт NULL//SHIFT собирается до упаковки. Сетевые функции отдельных игр и внешние проекты всё ещё требуют интернета. Для App Review нужно показать реальные игровые циклы на устройстве — сборка сама по себе не гарантирует одобрение Apple.

## Что добавлено

- capacitor.config.ts — Bundle ID, имя и путь запуска локального каталога.
- codemagic.yaml — два независимых ручных workflow: TestFlight и отправка на App Store Review.
- scripts/codemagic/build-ios.sh — тесты сайта, официальный Godot 4.7.2 Web export, Vite build, локальная упаковка каталога, генерация iOS-проекта и синхронизация плагинов.
- scripts/prepare-ios-dist.mjs — копирует сайт в mobile-dist, чинит локальный путь игры Time и добавляет нативный share bridge только в мобильные HTML-файлы.
- scripts/ios/native-share-bridge.ts — системная кнопка Share; не начисляет награду автоматически и не утверждает, что публичный пост подтверждён.
- scripts/ios/install-app-icon.mjs — генерирует 1024×1024 PNG из оригинальной эмблемы OSGARD и устанавливает её в Xcode Assets.
- scripts/ios-package-smoke.mjs и команда npm run qa:ios-package — проверяют игровые entry points, privacy route, share bridge, Xcode-проект и App Store icon.
- src/main.tsx — поддержка локального маршрута Time внутри мобильного пакета.

Сгенерированные каталоги ios/ и mobile-dist/ игнорируются Git: Codemagic строит их заново, а не полагается на закоммиченные Xcode-файлы.

## Однократная настройка Apple и Codemagic

Эти шаги требуют владельческого доступа — GitHub не может заменить аккаунты Apple/Codemagic.

1. Убедись, что активен Apple Developer Program, затем в Apple Developer зарегистрируй Bundle ID **world.osgard.play**. Если он занят или у тебя уже зарегистрирован другой ID, замени его одинаково в capacitor.config.ts и в обоих workflow в codemagic.yaml до первого сборочного запуска.
2. Создай приложение в App Store Connect с тем же Bundle ID и версией 1.0.0. Заполни App Information и возрастной рейтинг. Для нового приложения Apple ID записи — числовой App Store ID, не Bundle ID.
3. В Codemagic подключи репозиторий HADJAL001/osgard-world и выбери ветку feat/osgard-play-ios-codemagic-release для проверки конфигурации codemagic.yaml.
4. В Codemagic → Team integrations → Developer Portal добавь App Store Connect API key с доступом уровня App Manager. Назови integration reference **osgard_app_store_connect**. Храни файл .p8 только в Codemagic; не добавляй ключ в Git.
5. В Codemagic создай variable group **osgard_app_store** и переменную APP_STORE_APPLE_ID со значением числового Apple ID из App Store Connect.
6. В Code signing identities создай/подключи Apple Distribution certificate и App Store provisioning profile для **world.osgard.play** либо разреши Codemagic сгенерировать их через зарегистрированный Developer Portal integration.
7. Убедись, что приложению в App Store Connect назначены политика конфиденциальности, категория, контакты поддержки и необходимые соглашения о распространении.

API key и сертификаты должны находиться только в настройках Codemagic/Apple. Не печатай содержимое .p8, приватные ключи или секретные значения в логах.

## Запуск workflow

### 1. Сначала TestFlight

В Codemagic вручную запусти **OSGARD PLAY — iOS TestFlight**. Он:
- устанавливает зафиксированные версии Capacitor;
- прогоняет существующие smoke tests для каталога и игр;
- собирает Godot Web export и Vite bundle;
- запускает npm run qa:ios-package;
- создаёт подписанный IPA;
- загружает сборку в TestFlight.

Перед этим нужно предоставить Codemagic API key, App Store ID, сертификат и provisioning profile. Без этих ресурсов workflow ожидаемо остановится на настройке signing/publishing — это не дефект игрового кода.

### 2. Испытания на реальном iPhone/iPad

До App Review проверь:
- старт каталога без зависимости от загрузки удалённого сайта;
- все десять entry points и корректный запуск Time/NULL//SHIFT;
- полноэкранные/вертикальные и альбомные режимы, safe areas, сенсорный ввод и паузу/возврат там, где поддерживает игра;
- системное меню «Поделиться» и что оно выдаёт ссылку https://osgard.world/..., а не локальный capacitor://localhost;
- сценарии без сети и сценарии, которым нужен онлайн;
- локальную историю, избранное и сохранения каждой игры;
- отсутствие белого экрана, ошибок WebGL/Unity, блокирующих диалогов и недоступного управления.

Успешный IPA build не доказывает, что все игры прошли runtime QA на реальном устройстве.

### 3. Только после этого — App Store Review

Когда запись приложения в App Store Connect полностью заполнена, скриншоты сделаны с реального приложения, App Privacy и возрастной рейтинг проверены, вручную запусти **OSGARD PLAY — Submit to App Store Review**. Этот workflow выставляет submit_to_app_store: true и отправляет сборку на рассмотрение. Не запускай его до TestFlight-тестирования и заполнения метаданных.

### Прежде чем отправить

- Подготовь настоящие скриншоты с работающей сборки на поддерживаемых размерах экрана. Не используй концепт-рендеры как скриншоты игры.
- Заполни age-rating questionnaire по фактическому содержимому всех игр, онлайновым функциям и пользовательскому взаимодействию.
- Проверь App Privacy questionnaire с учётом согласия на аналитику и API-событий, которые есть в текущем коде.
- Убедись в правомерности материалов, музыки, шрифтов, игр и всех сторонних ресурсов.
- Прочти актуальные App Review Guidelines, особенно раздел 4.2: упаковка сайта без самостоятельной ценности может быть отклонена. Здесь игры включаются в пакет локально, однако итоговое решение остаётся за Apple.

## Текущие ограничения

- Этот PR подготавливает конфигурацию, но не может создать App Store record, принять соглашения Apple или загрузить секреты в Codemagic.
- У меня нет доступа к твоему Codemagic Team UI или приватному App Store Connect API key, поэтому пока не могу подтвердить подписанную сборку, TestFlight upload или отправку на review.
- Сборка и App Store review должны быть подтверждены в Codemagic после настройки владельческих credentials.
