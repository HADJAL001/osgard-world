# OSGARD WORLD / Games — технический аудит

Дата аудита: 13 октября 2026 г.  
Источник исходников: [HADJAL001/osgard-world](https://github.com/HADJAL001/osgard-world), ветка `master`.  
Статус исполнения: изменения этого цикла подготавливаются в отдельной ветке; пока PR не принят и публикация не завершена, считать их частью работающего production-сайта нельзя.

## 1. Что удалось подтвердить по исходникам

- Основной сайт: React 19, TypeScript 5.7, Vite 6; в зависимостях есть Three.js и lucide-react. `package.json` содержит сборку `npm run build`, проверку типов `npm run check` и отдельные QA-скрипты.
- Игровой каталог — отдельная статическая страница `public/games/index.html` с отдельным `public/games/player-lifecycle.js`, а не набор карточек главного React-компонента.
- Каталог описывает пять маршрутов: NULL//SHIFT, «Империя времени», SWARM, INHERIT и REMIX. В нём уже присутствуют поиск и фильтры, локальные избранное/история, диалог игрового окна, полноэкранный режим, обмен ссылкой, состояние загрузки/ошибки, повторный запуск, согласие на аналитику, блок экосистемы, форма связи и страницы политики/условий.
- SWARM — самостоятельная HTML-страница с canvas (`public/games/swarm/index.html`). INHERIT — большая самостоятельная HTML-игра (`public/games/inherit/index.html`) с локальным сохранением и собственной логикой. REMIX — самостоятельная HTML/canvas-страница (`public/games/remix/index.html`); для его сетевых сценариев необходим runtime-тест backend.
- «Империя времени» находится в React-компоненте `src/TimePrototype.tsx`; игровая логика импортируется из `src/core/timeState`.
- NULL//SHIFT имеет отдельный исходный проект Godot `godot/null-shift` и smoke-скрипт `scripts/null-shift-godot-smoke.mjs`. Каталог указывает веб-маршрут `/games/null-shift-godot/`; готовность экспортированного файла и успешный запуск в браузере должны подтверждаться сборкой и runtime-тестом отдельно.
- Игровая страница уже содержит рекламную партнёрскую секцию и десять ссылок на проекты экосистемы. На самой странице явно написано, что рекламная сеть не подключена; политика также сообщает, что checkout отсутствует. Поэтому в этом цикле не имитируются рекламные показы, платежи, подписчики или выручка.

## 2. Ограничения проверки

- Подключение к GitHub позволило читать исходники, но сетевой доступ из локальной оболочки недоступен, а браузерный fetch публичного сайта в этой проверке вернул cache-miss/ограничение доступа. Это не доказывает, что сайт недоступен для обычного пользователя; фактический production uptime здесь не подтверждён.
- Ветку `master` не изменяли. Новые файлы должны пройти сборку и QA в отдельной ветке до принятия PR.
- В текущей версии каталога события отправляются в `/api/v1/player/events` только при включённом пользователем согласии и наличии токена входа. Сервис/схема backend и фактическое сохранение событий должны проверяться отдельно.
- Форма заявки игрового каталога открывает WhatsApp с подготовленным сообщением. Она не отправляет заявку на сервер сама и не обеспечивает серверный inbox/антиспам.
- В коде основного `src/App.tsx` обнаружены повреждённые строки русской кодировки и недоказанные количественные обещания (например, проценты, время подачи, точные показатели экономии/дохода). Их исправление включено в этот набор изменений: copy заменяется на понятные продуктовые описания без неподтверждённых метрик.
- Есть расхождение имени домена продукта создания приложений: в массиве главного сайта указан `osgardnewworld.com`, а в каталоге/текущем брифе — `osgardbewworld.com`. До платной кампании нужно подтвердить канонический домен и привести все ссылки к одному адресу.

## 3. План по этапам

1. **Каталог и доверие.** Сохранить работающую витрину, устранить повреждённые строки, использовать уникальный SVG-знак вместо фотографии в роли favicon, добавить партнёрскую страницу.
2. **Измеримость.** Оставить аналитику выключенной по умолчанию; отправлять события только при согласии и авторизованной сессии. UTM-метки — это источник для атрибуции, а не доказательство конверсии.
3. **Коммерческий пилот.** Сначала тестировать спонсорский блок и разработку брендированных заданий вручную. Отдельно документировать подтверждённые показы, клики, лиды и договоры.
4. **Серверная часть.** Проверить API-схему, задержку/дедупликацию событий, ограничения частоты, аутентификацию админки и политику хранения. Клиентский код не может быть единственным источником истины для оплат и наград.
5. **Платежи/реклама.** Подключать только после выбора одобренного провайдера, проверки доступности по географии и доработки privacy/terms. До этого checkout и рекламные SDK должны оставаться отключёнными.
6. **Релиз.** `npm run check`, `npm run build`, `npm run qa:games-portal`, новый `npm run qa:partner-studio`, route matrix и ручные тесты на Android/iOS/desktop; отдельно проверить экспорт Godot и сетевую игру REMIX.

## 3.1. Дополнительное исследование коммерческих каналов

В `docs/OSGARD-GAMES-MONETIZATION-OPTIONS.md` задокументированы официальные правила CrazyGames, GameDistribution, Google Ad Manager rewarded ads и Google AdSense. Важные выводы: CrazyGames требует отдельную интеграцию SDK для монетизации Full Launch и ограничивает кросс-промо внутри игры; rewarded ads требуют явного выбора пользователя и подтверждённого события выдачи награды; обычные AdSense-блоки нельзя стилизовать под игровой интерфейс или ставить рядом с игровыми кнопками так, чтобы провоцировать случайные клики.

## 4. Что не сделано этим PR

Не публикуется обновление production-сайта; не подключаются рекламные сети, платёжные ключи, подписка, серверная админ-панель или новые cookies; не создаётся фиктивная статистика. Партнёрская страница и калькулятор работают как клиентская подготовительная студия. Управление рекламным инвентарём с сервера появится только после отдельной проверки backend и авторизации.
