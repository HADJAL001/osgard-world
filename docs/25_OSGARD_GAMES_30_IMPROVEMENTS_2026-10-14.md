# OSGARD WORLD GAMING — 30 улучшений Player Lab
Дата: 14 октября 2026 г.  
Репозиторий: HADJAL001/osgard-world, базовая ветка master.  
Формат: дополнительный lazy-loaded модуль каталога. Основной React/Vite портал и игровые движки не переписываются.

## Аудит перед изменениями

В master уже есть React 19 + Vite 6 + TypeScript, 11 игровых точек входа, каталог /games, карточки с жанрами, локальные избранное и недавние игры, игровая оболочка, согласуемая аналитика, постигровые рекомендации, каталог экосистемы, commerce API и защищённая commerce-admin. Переход на единый игровой движок был бы технически необоснованным: NULL//SHIFT имеет Godot/Web export, REMIX использует Unity WebGL, остальные игры — браузерные/React клиенты.

Публичный сайт https://osgard.world и десять сайтов экосистемы не удалось независимо получить через доступный web fetch (ошибка Cache miss/недоступность источника в инструментарии). Репозиторий доступен через GitHub API. Это не доказывает, что сами домены недоступны пользователям. Изменения делаются в отдельной ветке и не публикуются на production автоматически.

## 30 изменений

1. В каталоге добавлен отдельный пульт игрока, не заменяющий существующую витрину.
2. Пульт загружается только вместе с существующим lazy-enhancement потоком, не блокируя первый экран.
3. Нативный dialog, подписи и статусные сообщения дают понятную клавиатурную семантику.
4. Горячая клавиша ? открывает пульт вне полей ввода.
5. Локальный профиль считает фактические открытия игрового окна на этом устройстве.
6. Отдельно считается количество разных игр, которые открывались через каталог.
7. Время считается только пока окно игры открыто и вкладка видима; это не равно времени активного управления.
8. Активность группируется по датам на устройстве и не отправляется на сервер.
9. Пять персональных достижений строятся из локальных событий, без рейтингов и заявлений о других игроках.
10. Следующая игра выбирается из неоткрытых на этом устройстве; алгоритм объясняет причину рекомендации.
11. Очередь ограничена пятью элементами.
12. Повторное добавление одной игры не создаёт дубликат.
13. Порядок очереди можно менять кнопками вверх/вниз.
14. Игры можно удалять из очереди по одной.
15. Следующую игру очереди можно запустить напрямую через существующую оболочку.
16. На карточках есть отдельная кнопка добавления в очередь, не конфликтующая с «Играть».
17. Личный недельный маршрут предлагает попробовать три жанра.
18. Прогресс маршрута считается только по реально открытым играм в журнале пульта.
19. Ссылка на игру создаётся с понятными UTM-метками источника, кампании и игры.
20. Используется системный Web Share API, а при его отсутствии — Clipboard API без выдуманных кликов.
21. Диагностика проверяет HTTP-маршруты 11 игр на текущем домене.
22. При неподдерживаемом HEAD проверка повторяет безопасный GET.
23. Каждый запрос ограничен тайм-аутом 6 секунд.
24. Состояние online/offline отражается на кнопке пульта и обновляется событиями браузера.
25. Доступная оценка quota/usage локального хранилища показывается как приближение браузера.
26. Диагностика сообщает о поддержке WebGL 2, fullscreen, share, clipboard, Service Worker и Storage API.
27. Считается число загруженных ресурсов текущего origin и медленных загрузок; приватные сторонние URL не выгружаются.
28. Настройка уменьшения анимации уважает системное предпочтение при первом запуске.
29. Отдельный режим высокого контраста повышает читаемость пульта и фокусных состояний.
30. Масштаб текста пульта настраивается на 90/100/110/120%.

## Безопасность и приватность

- Новая история, очередь, статистика и настройки остаются в localStorage.
- Новая функция не подключает рекламные SDK и не отправляет телеметрию. Диагностика выполняет HTTP-запросы только к маршрутам текущего сайта при явном нажатии.
- Экспорт содержит только игровые ID, историю запусков и настройки. Он не включает email, телефон, invite-коды, токены авторизации и серверную аналитику.
- Импорт ограничен 100 KiB, принимает только формат/версию схемы, известные ID текущего каталога и проверенные числовые диапазоны.
- Удаление очищает локальное избранное, историю, очередь и профиль пульта; аналитическое согласие не трогается.
- Все отображаемые динамические значения вставляются через textContent; импортируемые строки не трактуются как HTML.
- Счётчики локального пульта не являются межустройственной/серверной аналитикой и не показываются как общие метрики платформы.

## Проверки

Добавлен smoke-контракт scripts/player-console-smoke.mjs и npm script qa:player-console; PR workflow запускает его рядом с имеющимися проверками каталога. Smoke-проверка статическая: она не заменяет ручной QA на Chrome/Safari/iOS/Android. Полная сборка сайта/CI должна быть выполнена GitHub Actions после открытия PR.

## Не активировано / следующий бизнес-шаг

- Рекламные сети, reward callbacks и реальные рекламные показы не подключены.
- Включение checkout/Premium по-прежнему зависит от провайдера, ключей, webhook-секретов и серверных прав доступа.
- Live статус внешних сайтов экосистемы не подтверждён доступной веб-проверкой.
- Перед включением платной рекламы подтвердить фактическую доступность доменов, назначение карточек и правовые страницы.
