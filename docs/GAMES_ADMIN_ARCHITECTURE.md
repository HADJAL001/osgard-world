# OSGARD Games — архитектура панели управления

**Статус: не реализована и не опубликована.** Текущая ветка не добавляет клиентскую «админку» с фиктивной защитой. В проверенном коде есть пользовательский API и очередь событий, но отдельный подтверждённый административный контракт с правами ролей и CRUD для каталога не установлен.

## Граница безопасности

Нельзя полагаться на скрытый URL, пароль в JavaScript, флаг в localStorage или клиентскую проверку роли. Каждый административный запрос должен проверяться на сервере. Пользовательский JWT сам по себе не должен давать административные полномочия.

Перед реализацией требуются:
- явная серверная роль/набор разрешений и проверка прав на каждом маршруте;
- аудит изменений, ограничение частоты запросов и серверная валидация;
- защита CSRF, если применяются cookie-сессии;
- секреты только в серверном хранилище;
- журнал доступа и возможность отзыва сессий.

## Предполагаемые сущности

- **Игра:** адрес запуска, жанр, теги, версия, поддерживаемые устройства/управление, статус, видимость, описание, обложка, SEO, связанные игры.
- **Размещение:** место на витрине, формат, список игр, расписание, ограничение частоты, согласованные регионы и требования к согласию.
- **Спонсорская кампания:** бренд, материалы, даты, правила маркировки, бюджеты/договорные условия и статус утверждения.
- **Покупка/доступ:** идентификатор провайдера, подтверждённый серверный статус, возврат, права на контент. Не хранить платёжные реквизиты карточки.
- **Аналитическое событие:** разрешённое имя события, игра, время, источник, consent context, версия схемы. Не записывать лишние персональные данные.
- **Заявка:** тема, согласованный контакт, статус обработки, срок хранения и доступ ответственных сотрудников.

## Порядок реализации

1. Уточнить существующий API и источник авторизации.
2. Добавить роли/разрешения в backend и тесты запрета доступа.
3. Определить схему каталога и безопасные CRUD endpoints.
4. Подключить только первую полезную функцию — обновление описаний/статуса игр.
5. Затем добавить спонсорские размещения, отчёты и заявки.
6. Интегрировать оплату лишь после выбора провайдера, серверных webhook, идемпотентности и возвратов.

Пока этих условий нет, каталог остаётся статическим и не изображает управление теми данными, для которых серверная интеграция не готова.
