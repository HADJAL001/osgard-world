# OSGARD WORLD GAMES — порядок выпуска и проверки

Дата аудита: 13 октября 2026 года.

Документ описывает текущие исходники и конвейер публикации. Сам по себе он не подтверждает, что последняя версия уже опубликована на production.

## Архитектура

- Главная игровая витрина — единая статическая страница /games/ в public/games/index.html. Не создавайте второй каталог на этом же адресе в React.
- Индивидуальные страницы игр — /game/:slug, компонент src/GameDetailPage.tsx, маршрутизация в src/main.tsx.
- Империя времени — /games/time, React/TypeScript.
- SWARM — независимая браузерная игра в public/games/swarm/.
- NULL//SHIFT — основной игровой клиент: Godot Web export, генерируемый при публикации в public/games/null-shift-godot/. Резервный браузерный WebGL-клиент остаётся в public/games/null-shift/.
- INHERIT — самостоятельная HTML-игра в public/games/inherit/.
- REMIX — веб-клиент и ресурсы Unity/WebGL в public/games/remix/. Сетевые функции зависят от доступности соответствующего API.
- Файлы экспорта Godot создаются в GitHub Actions; отсутствие сгенерированных .wasm и .pck в исходной ветке не означает, что в production-конвейере экспорта нет.

## Проверка перед изменениями и локальный запуск

Работать нужно из корня репозитория. Устанавливайте зависимости из lock-файла, не заменяя весь стек сайта игровым движком.

Последовательность основной проверки:

1. npm ci
2. npm run check
3. npm run qa:games-portal
4. npm run qa:games-detail
5. npm run qa:null-shift
6. npm run qa:null-shift-godot
7. npm run qa:games-model
8. npm run qa:partners-page
9. npm run qa:ecosystem
10. npm run build
11. npm run preflight:frontend
12. npm run qa:production-routes

После реального Godot Web export выполняется отдельная проверка экспортированных файлов:

node scripts/null-shift-godot-smoke.mjs --export-check public/games/null-shift-godot

Эта проверка должна найти HTML, JS, WebAssembly и PCK с ожидаемыми минимальными размерами, а также проверить премиальную загрузочную оболочку. Один только HTML-файл не подтверждает готовность игры к запуску.

## Что делает публикационный workflow

1. Устанавливает зависимости, проверяет TypeScript и выполняет текущие smoke-тесты игр.
2. Устанавливает официальный Godot 4.7.2 и шаблоны Web export в runner GitHub Actions.
3. Импортирует и разбирает проект Godot в headless-режиме.
4. Запускает headless runtime-smoke, проверяющий игровые состояния и переходы.
5. Экспортирует Godot Web в public/games/null-shift-godot/ и проверяет полученные артефакты.
6. Собирает сайт, запускает проверки статических файлов и упаковывает release-архив.
7. Проверяет контрольную сумму архива, активирует архив через существующий контролируемый deployment flow и запускает production route matrix.

Фактическое выполнение этих шагов следует подтверждать по результату конкретного workflow run; наличие YAML-конфигурации не доказывает, что последний релиз прошёл успешно.

## Ручное тестирование на компьютере и телефоне

CI и headless-тесты не заменяют проверку на физических устройствах. Перед выпуском проверить:

- ширины 320, 375, 768 и 1280 пикселей; отсутствие горизонтальной прокрутки и перекрытия игровых кнопок;
- поиск, категории, фильтры, избранное и полку недавно открытых игр;
- карточку каждой игры, прямую ссылку запуска, возврат в каталог, шаринг и полноэкранный режим;
- фактический запуск Godot/WebGL, отображение ошибки несовместимости и переход к браузерной резервной версии;
- сенсорные кнопки NULL//SHIFT и SWARM, а также управление клавиатурой и мышью;
- локальное сохранение INHERIT, загрузку ресурсов REMIX и доступность сетевого API, если проверяется онлайн-режим;
- старт и завершение игровой сессии: загрузка iframe HTML не должна приниматься за подтверждение игрового старта;
- отключённую по умолчанию аналитику, явное согласие, поведение после отказа и корректное завершение сессии;
- браузерную консоль, сетевые ошибки, Content-Type ресурсов, заголовки и SEO-метаданные;
- переходы по старым URL, sitemap и корректность всех пяти страниц /game/:slug.

## Коммерческие границы текущей версии

- /games/monetization/ — локальная сценарная модель. Её eCPM, fill rate, конверсии, средний чек и расходы являются предположениями, а не фактической выручкой или данными аудитории.
- /games/partners/ — партнёрский инвентарь и запрос на интеграцию. Наличие страницы не означает, что рекламная сеть, рекламные показы или спонсорские выплаты активированы.
- Rewarded video требует подтверждённого callback провайдера, серверной проверки одноразовой награды и защиты от повторного начисления.
- Продажа игры, подписка и внутриигровые покупки требуют checkout, проверки подписей вебхуков, модели прав на сервере, идемпотентности, возвратов и поддержки. Клиентская отметка не является подтверждением оплаты.
- Форма заявки сейчас ведёт пользователя к подготовленному сообщению/почтовому приложению; её нельзя считать подтверждённой записью в серверную CRM.
- UTM-параметры на переходах помогают атрибуции только если принимающий сайт действительно сохраняет источник в своей аналитике.
- Ссылки на внешние проекты внесены по предоставленному владельцем списку. Их live-доступность и функции необходимо подтверждать отдельной проверкой.

## Безопасность и публикация

- Не помещать секретные ключи, токены провайдеров и серверные credentials в public/, игровые файлы или клиентский React-код.
- Публикация выполняется существующим workflow, использующим настроенные GitHub Actions secrets для сервера. Не копировать секреты в репозиторий.
- Правовые страницы являются стартовыми документами. Перед коммерческим запуском определить юридического оператора, применимое право, сроки хранения, каналы запросов пользователей и требования возрастной аудитории.
- Считать выпуск готовым только после успешных CI-проверок, реальной проверки экспортированных Godot-артефактов и успешной production route matrix. После этого отдельно провести ручной smoke на компьютере и телефоне.
