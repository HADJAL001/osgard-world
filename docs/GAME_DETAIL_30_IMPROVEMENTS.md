# OSGARD PLAY — 30 улучшений игрового цикла

Дата: 14 октября 2026 года. Ветка: `feat/osgard-play-30-improvements-rebased`.

## Реализовано в исходниках

1. Проверка origin перед обработкой lifecycle-сообщений.
2. Проверка `event.source` на активный iframe, а не только на same-origin.
3. Проверка соответствия сообщения выбранной игре.
4. Allowlist допустимых состояний lifecycle.
5. Проверка типа протокола `osgard:game-lifecycle`.
6. Проверка формата ID игры.
7. Проверка конечности timestamp.
8. Отбрасывание сообщений от предыдущего запуска.
9. Отбрасывание неправдоподобных timestamp из будущего.
10. Ограничение поля сообщения об ошибке до 500 символов.
11. Единый монотонный таймер игровой сессии.
12. Повторный старт таймера отклоняется.
13. Время загрузки iframe не считается игровым временем.
14. Идемпотентная постановка на паузу.
15. Идемпотентный возврат с паузы.
16. Время скрытой вкладки исключается из длительности.
17. Составные причины паузы: состояние игры и фоновой вкладки.
18. Не более одного события начала сессии.
19. Не более одного события завершения сессии.
20. Нет фиктивной длительности, если игра не дошла до реального старта.
21. Событие завершения содержит длительность, причину выхода и способ старта.
22. Для совместимых клиентов предусмотрен старт по первому действию пользователя в iframe.
23. Тайм-аут подтверждения готовности ограничен 18 секундами.
24. Добавлена кнопка повтора запуска внутри экрана ошибки.
25. Сохранено открытие игры в отдельной вкладке как fallback.
26. Состояния загрузки и ошибки доступны скринридеру.
27. Фокус переводится в игру при запуске и возвращается к кнопке запуска после закрытия.
28. Состояние fullscreen отражается в `aria-pressed`; неподдерживаемый API обрабатывается.
29. Выбор RU/EN сохраняется локально.
30. Избранное, история, согласие и язык синхронизируются между вкладками; локальные списки нормализуются по известным ID и ограничены по размеру.

## Уточнение аналитики

- `share_dialog_opened` означает открытие интерфейса отправки.
- `share_link_copied` фиксируется только после успешного копирования.
- Успешное закрытие системного Web Share API не доказывает фактическую доставку сообщения и не записывается как подтверждённая отправка.
- Начало и завершение игровой сессии передаются только при действующем согласии на аналитику.

## Проверки

`npm run qa:game-detail-runtime` содержит 37 детерминированных сценариев для таймера и доверия к сообщениям. Тест подключён к frontend validation, deploy smoke и release-readiness. Production build/deploy считается проверенным только после завершения соответствующего GitHub Actions workflow.
