# OSGARD PLAY — 30 улучшений игрового цикла

Дата: 14 октября 2026 года. Ветка: `feat/osgard-play-30-improvements`.

## Выполнено в исходниках

1. Проверка origin перед обработкой lifecycle-сообщений.
2. Проверка `event.source` на активный iframe, а не только на same-origin.
3. Проверка соответствия сообщения выбранной игре.
4. Allowlist состояний lifecycle вместо доверия произвольной строке.
5. Проверка типа протокола `osgard:game-lifecycle`.
6. Проверка формата ID игры.
7. Проверка конечности timestamp.
8. Отбрасывание сообщений, пришедших до текущего запуска.
9. Отбрасывание неправдоподобной метки времени из будущего.
10. Ограничение поля сообщения об ошибке до 500 символов.
11. Единый монотонный таймер сессии.
12. Повторный старт таймера отклоняется.
13. Время загрузки iframe не входит в игровую длительность.
14. Повторная постановка сессии на паузу безопасна.
15. Повторный resume безопасен.
16. Время скрытой вкладки исключается из длительности.
17. Составные причины паузы: игра и вкладка.
18. Не более одного события старта сессии.
19. Не более одного события завершения сессии.
20. При завершении до реального старта не возникает фиктивная длительность.
21. Событие завершения содержит длительность, причину выхода и способ старта.
22. Для совместимых игровых клиентов предусмотрен старт по первому реальному действию внутри iframe.
23. Тайм-аут подтверждения готовности ограничен 18 секундами.
24. Добавлена кнопка повтора запуска прямо в экране ошибки.
25. Сохранён вариант открытия игры в отдельной вкладке.
26. Состояния загрузки и ошибки доступны скринридеру.
27. Фокус переводится в игровой экран при запуске и возвращается к кнопке после закрытия.
28. Полноэкранный режим отражается в `aria-pressed`; неподдерживаемый API обрабатывается.
29. Выбор RU/EN сохраняется локально.
30. Избранное, история, согласие и язык синхронизируются между вкладками; локальные списки фильтруются по известным ID и ограничиваются по размеру.

## Уточнение аналитики

- `share_dialog_opened` означает открытие интерфейса обмена ссылкой.
- `share_link_copied` возникает только после успешного копирования.
- Успешное закрытие Web Share API само по себе не доказывает отправку получателю и не записывается как подтверждённая отправка.
- События начала/завершения отправляются только при существующем согласии на аналитику.

## Проверки

`npm run qa:game-detail-runtime` содержит 37 детерминированных сценариев для таймера и доверия к сообщениям. Тест включён в frontend validation, deployment smoke и release-readiness. Полный TypeScript build и production deployment считаются подтверждёнными только после фактического результата соответствующего GitHub Actions workflow.
