# OSGARD WORLD Gaming — каталог под управлением редактора

Дата: 14 октября 2026 года. Изменения находятся в отдельной ветке и должны пройти CI и review до публикации.

## Что добавлено

- Серверный реестр одиннадцати зарегистрированных игр в `services/osgard-commerce-api/src/game-catalog.mjs`.
- Хранение изменений в PostgreSQL `commerce_game_catalog` с одноразовым seed: существующие значения не перезаписываются на перезапуске.
- Публичный API `GET /v1/game-catalog`: возвращает управляемый каталог из БД, а если БД ещё не готова — безопасный статический реестр.
- Операторские API `GET/POST /v1/admin/game-catalog` защищены существующим `ADMIN_API_TOKEN` (Bearer), ограничением частоты запросов и ответами `no-store`.
- Интерфейс `/games/admin/catalog/` позволяет изменить название, описание, жанры, видимость, признак выделения, статус прототипа и порядок существующей карточки.
- Публичная страница применяет безопасные текстовые изменения на `/games/` с таймаутом и fallback на статические карточки.
- URL запуска не редактируются: сервер восстанавливает их из собственного allow-list. Добавление новой игры по-прежнему требует кода, сборки и route QA.

## Безопасность и границы

Токен остаётся только в памяти вкладки редактора; API использует Bearer-аутентификацию и серверную проверку. Чувствительные данные не записываются в браузерное хранилище. Значения каталога рендерятся через `textContent`, не как HTML. Админ-страница помечена `noindex`, но это не является защитой доступа: безопасность записи обеспечивает только API.

Редактор управляет только текстовыми метаданными существующего списка из 11 игр. Он не удаляет исходные файлы, не меняет URL клиентов, не включает рекламу, не активирует checkout и не создаёт фиктивную аналитику.

## Тестирование и публикация

- `node --test services/osgard-commerce-api/test/game-catalog.test.mjs` — контракт серверной валидации.
- `node scripts/game-catalog-admin-smoke.mjs` — статическая интеграция редактора, runtime, безопасности и route matrix.
- `npm run qa:games-portal` будет запускать контракт каталога в конце существующей регрессии.
- Route matrix проверяет HTML, JS, публичный JSON и ожидаемый auth-guard администратора.

После PR нужно проверить green CI, слить в `master` и подтвердить публичные маршруты в production route matrix. Сам факт создания ветки/PR не развёртывает сайт.

## Важные переменные

Используется существующий `DATABASE_URL` и `ADMIN_API_TOKEN` Commerce API. Новые секреты не нужны. Если БД недоступна, публичная витрина продолжит работать на статическом содержимом; операторская запись завершится сообщением об ошибке и не покажет ложный успех.
