# OSGARD PLAY — referral contract and measurement boundaries

**Purpose:** keep game sharing, campaign links and referral analytics interoperable. This document describes the deployed design contract, not measured performance.

## Canonical invitation

The standard Games invitation uses `/games/?og_ref=og_[8 hex digits]&og_game=<game-id>` and the UTM tuple `utm_source=osgard_play`, `utm_medium=referral`, `utm_campaign=play_with_friends`, `utm_content=<game-id>`.

Older campaign links may still use `challenge=<game-id>&ref=<12 hex digits>` with `utm_source=osgard_games`, `utm_medium=referral`, `utm_campaign=play_with_a_friend`. Treat these as a compatibility path; new tools should emit the canonical form.

## Event funnel

- `share_created`: browser-confirmed native share completion or successful clipboard copy. It does **not** prove message delivery.
- `referral_link_opened`: a valid invite URL was opened while analytics consent was enabled. It is not necessarily a unique person.
- `game_session_started` and `game_session_completed`: separate gameplay lifecycle events attributed when a valid referral token was captured with consent.
- Commerce dashboard counts are consented event counts for a 30-day window; do not relabel them as unique users, total visits or sales.

## Consent and deduplication

Analytics is off unless the existing catalogue consent is explicitly enabled. Referral-open callbacks mark an event `pending` before the first network wait to avoid overlapping submissions in the same browser tab. Requests are aborted where supported when consent is withdrawn; consent is checked again after configuration fetches and before event posting. A request already accepted by the server before revocation cannot be undone by the browser.

The browser session stores the referral code and timestamp, not a user's name, email or account identifier. Analytics/API failures should leave the game playable and allow a later visible-page retry.

## Commercial guardrails

Ad impressions, rewarded views, purchases, subscriptions and sponsor revenue are not generated by this referral subsystem. Connect those only to actual providers, verified server-side callbacks and production order records. A modeled K-factor is a hypothesis until calculated from real cohorts over a defined period.
