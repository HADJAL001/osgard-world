# OSGARD WORLD GAMING — технический аудит и план запуска
Дата: 2026-10-13  
Статус: changes prepared on branch \`feat/games-growth-readiness-2026-10\`; production has not been changed by this work.

## 1. Что реально обнаружено в репозитории

- Основной проект \`HADJAL001/osgard-world\` использует React 19, Vite 6 и TypeScript 5.7. \`npm run build\` выполняет синхронизацию ресурсов SWARM, проверку типов и production-сборку.
- Игровая витрина — отдельный статический документ \`public/games/index.html\`; в ней уже есть каталог пяти игр, поиск, фильтры, избранное и история в локальном хранилище, полноэкранный запуск, окно запуска через iframe и передача ссылок.
- Игры имеют разные точки входа: Империя времени — \`/games/time\`; SWARM — \`/games/swarm/\`; INHERIT — \`/games/inherit/\`; REMIX — \`/games/remix/\`; NULL//SHIFT — текущая браузерная WebGL-версия \`/games/null-shift/\` и исходный проект Godot \`godot/null-shift/\`.
- Для NULL//SHIFT в репозитории есть Godot 4.x-проект, HTML-shell, web export preset и отдельные source-smoke проверки. Но собранные файлы Web (\`index.js\`, \`index.wasm\`, \`index.pck\`) не включены в ветку и исключены из Git. На проверенной точке сборки прямого маршрута для экспортированной игры не было. Теперь маршрут \`/games/null-shift-godot/\` содержит честный экран-переход к существующей WebGL-версии, пока настоящий export не создан.
- Уже существующая игровая аналитика не безусловна: витрина хранит избранное/историю локально, а отправка некоторых событий требует явного согласия пользователя и токена аутентификации. Это следует сохранить.
- Уже существовали страницы условий и конфиденциальности. Реклама и платёжный провайдер не были подключены; в витрине это прямо указывается.

## 2. Изменения в этой ветке

### Маршрут и сборка Godot
- Добавлен адаптивный fallback на \`public/games/null-shift-godot/index.html\`: не выдаёт fallback за Godot, объясняет причину и открывает доступную WebGL-версию.
- Обновлено правило Git ignore: fallback HTML отслеживается Git, а сгенерированные JS/WASM/PCK остаются исключёнными.
- Добавлен \`scripts/export-godot-web.mjs\`. Если Godot 4.x и шаблоны Web установлены, сборка сначала создаёт Vite \`dist\`, затем экспортирует Godot в \`dist/games/null-shift-godot/\` и проверяет размеры артефактов и shell. Если движка нет, обычная сборка оставляет fallback и явно пишет предупреждение. Для строгого релиза установите \`OSGARD_REQUIRE_GODOT_EXPORT=1\`.
- \`npm run qa:null-shift-godot\` дополнительно проверяет, что маршрут — либо полный экспорт, либо документированный fallback. Статический анализ не заменяет запуск игры самим движком.

### Финансовая модель игровой экосистемы
- Добавлена страница \`/games/monetization/\` с тремя сценариями: осторожным, базовым и оптимистичным.
- Все параметры меняются пользователем; результат пересчитывается локально, JSON можно сохранить на устройстве. Введённые значения не отправляются серверу.
- Добавлен детерминированный smoke-тест \`scripts/games-monetization-smoke.mjs\`.
- Значения по умолчанию — демонстрационные допущения для проверки формул, а не сведения о трафике OSGARD и не утверждённые рыночные ориентиры. Рекламные выплаты и оплаты пользователей не симулируются как реальные.

### Коммуникация и кросс-промо
- На витрину добавлена ссылка «Экономика игр».
- После закрытия игрового окна появляется локальная рекомендация следующей игры; выбор хранится только в браузере и использует простую ротацию, а не заявляет о персональном ИИ.
- На главной странице и странице каталога заменены неподтверждённые числовые обещания (например, фиксированный процент защиты, нулевой уровень ошибок, определённое время подачи машины, финансовые результаты и «экономия») на описания направлений.
- Исправлен адрес OSGARD New World: \`https://osgardbewworld.com\` вместо ошибочного \`osgardnewworld.com\`.
- Кросс-промо использует UTM-параметры. Клики не имитируются, счётчики аудитории/дохода не выдумываются.

## 3. Как запустить

В корне репозитория:
\`\`\`bash
npm install
npm run check
npm run qa:games-portal
npm run qa:games-model
npm run qa:null-shift-godot
npm run build
npm run preview
\`\`\`
Затем открыть \`http://localhost:4173/games/\` и \`http://localhost:4173/games/monetization/\`.

Для реального Godot Web export:
1. Установить Godot 4.7.x и экспортные шаблоны той же версии с официального сайта.
2. Убедиться, что исполняемый файл доступен как \`godot\` / \`godot4\` либо указать абсолютный путь через \`GODOT_BIN\`.
3. Выполнить \`npm run build\`. Если редактор или templates отсутствуют, сборка не выдаёт вымышленный результат: оставляет fallback. Для обязательного нативного web-экспорта задайте \`OSGARD_REQUIRE_GODOT_EXPORT=1\`.
4. Проверить маршрут, клавиатурное и сенсорное управление, FPS и размер/время загрузки на реальных устройствах.

## 4. Бизнес-модель и ограничения формул

Страница сценариев рассчитывает:
- Рекламные показы = игровые сессии × рекламные места на сессию × заполнение.
- Доход от рекламы = оплаченные показы ÷ 1 000 × eCPM.
- Доход от первого платежа = посещения × доля оплат × средний первый платёж.
- Заказы на разработку = посещения × конверсия в заявку × конверсия в оплаченный заказ.
- Ориентировочный операционный результат = доход от рекламы + платежи + разработка − платёжная комиссия − заявленные постоянные расходы.

В модель намеренно не входят повторяющиеся подписочные платежи, возвраты, налоги, доля платформ, рекламные ограничения, удержание пользователей и дополнительные расходы, если оператор их не добавил. Поэтому результат — не бухгалтерская прибыль и не обещание дохода.

## 5. Что остаётся до коммерческого запуска

- **Проверка доменов:** в этой рабочей среде не получилось надёжно проверить HTTP-доступность всех десяти сторонних доменов. Наличие URL в каталоге не означает, что сайт работает или поддерживает заявленную функцию. Нужно проверить их из нескольких сетей и согласовать описания с фактическими страницами.
- **Рекламные сети:** выбрать допустимого поставщика и географию, подключить аккаунт владельца, согласие, правила показов и защиту от некорректных событий. Сейчас реальная реклама не включена.
- **Платежи/Premium:** подключать только после выбора провайдера; проверку платежей и права доступа реализовать на сервере с webhook и идемпотентностью. Не хранить секреты в браузере. Сейчас реальные платежи не подключены.
- **Вознаграждаемая реклама:** не выдавать бонусы без проверяемого callback/S2S подтверждения провайдера и защиты от повторной выплаты.
- **Админ-панель:** требуется аутентификация с ролями, журнал изменений, серверная валидация и ограничения запросов. Не превращать публичную страницу каталога в админку с секретным ключом.
- **Метрики в реальном времени:** задать схему событий и ретенцию, получать реальные запуски/сессии/оплаты с сервера, учитывать согласие и возраст аудитории; отчёт должен различать наблюдённые значения и модельные оценки.
- **Юридическая проверка:** текущие страницы — стартовая документация, а не заявление о полном соответствии GDPR/CCPA и другим законам. Требуются проверка юристом и настройка под аудиторию, рекламные и платёжные сервисы.
- **Релиз и публикация:** эта работа подготовлена в отдельной Git-ветке. Она не была смёржена в \`master\` и не меняла опубликованный сайт. После ревью нужно смёржить PR, дождаться deployment, а затем выполнить production route matrix.
